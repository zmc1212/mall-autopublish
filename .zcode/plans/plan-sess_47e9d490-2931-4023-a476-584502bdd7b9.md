# 系统优化建议与实施计划

## 现状诊断（已核实）

架构：pywebview 桌面壳 + FastAPI 本地服务 + React 19/Tailwind 4 前端（约 2400 行）+ 单线程 JobManager + web_fill Playwright 流水线。整体结构清晰、可访问性意识良好，会话持久化（断点续跑、执行历史、指纹守卫）设计细致。短板集中在：前端反馈机制"只进不出"、全量轮询架构、异常静默吞噬、日志分散、缺"入库回查"闭环。

---

## 一、UI/UX 优化建议

### P0 — 日常体验（已逐一核实）
1. **通知系统重构**：错误红条与成功绿条永不消失、无关闭按钮（`desktop/ui/src/App.tsx:202-211`）；轮询成功会自动清掉动作错误（`App.tsx:164`），真实失败可能"闪没"。→ 改为统一 toast：分级（成功/警告/错误）、自动消失、可手动关闭、错误可展开重试。
2. **api.ts 错误解析 bug**：`response.json()` 失败后在 catch 里再 `response.text()`，body 已被消费会抛 "body already read"（`desktop/ui/src/api.ts:12-17`）；fetch 无超时/AbortController，后端挂起时轮询 promise 永久 pending。→ 修复解析 + 全局 15s 超时。
3. **全局单一 busy**：一个布尔禁用四个页面所有按钮（`App.tsx:83`），长动作（扫描大工作空间）期间整个 UI 像冻结。→ 改为按动作的 pending key，按钮级 spinner。
4. **轮询负载**：每 1.2s 拉全量 `/api/status` 含全部 rows+logs（`App.tsx:172-174`），数据多时大 JSON + 全树 re-render；LiveSteps 每次对整个日志数组做 JSON.stringify（`LiveSteps.tsx:11`）。→ 至少：页面隐藏时降频/暂停；后端加数据版本号，无变化返回 304 式轻负载；LiveSteps 用长度+末条指纹替代全量序列化。

### P1 — 一致性与代码健康
5. **设置水合 bug**：`settingsDraft` 只在首次水合，保存后或后端变更后 UI 永久脱钩（`App.tsx:149-155`）；首帧 `setConfirmSubmit(EMPTY_SETTINGS.confirm_submit)` 会覆盖用户前 1.2s 的勾选（`App.tsx:152`）；`confirm_submit` 不从服务端读取，刷新即丢。→ 修正水合时机与持久化链路。
6. **破坏性操作用原生 `window.confirm`**（`RunPanel.tsx:91`），与应用内自绘弹窗风格割裂 → 统一 ConfirmDialog，清除记录支持撤销。
7. **弹窗可访问性**：DataTableDialog 无焦点陷阱/焦点归还；ScanDecisionDialog 不支持点遮罩关闭；日志容器用 `aria-live` 会被读屏刷屏（`LiveSteps.tsx:31`、`SettingsPanel.tsx:90`）。
8. **表格体验**：明细表硬编码 `w-[1580px]`/`w-[1180px]` 窄窗口必出横向滚动（`WorkbookPanel.tsx:417`、`RunPanel.tsx:256`）；分页逻辑在两处重复实现 → 抽公共分页 hook。
9. **数字输入静默回退不一致**：设置页输错端口号静默变回 9222（`SettingsPanel.tsx:163-165`），执行页 limit 却有校验提示 → 统一校验反馈。
10. **输入框回跳竞态**：清空清单路径输入后，下一次轮询会把旧路径回填（`App.tsx:139-140`）。
11. **App.tsx（387 行 17 个 state）与 WorkbookPanel（498 行）拆分**：状态按面板收拢（useReducer/context），拆出扫描决策、明细表格等子组件。

### P2 — 打磨
12. 快捷键（Ctrl+1..4 切导航、空格暂停）；扫描错误多行展示而非一段 `<p>`（`WorkbookPanel.tsx:211-215`）；复制失败给反馈（`ProductItemId.tsx:48-50`，弃用 execCommand）；清理死代码（`api.ts:25,27,45`）；深色模式。

## 二、功能设计优化建议

### P0 — 稳定性与闭环
1. **提交结果回查闭环（最重要）**：提交后仅靠页面文案返回"结果待核实"（`web_fill/pipeline.py:598-622`），不回查仓库确认入库（README:73 自认缺失）→ 提交后按 item_id 只读打开商品/SKU 管理页核验（可复用 material_import 的 `inspect_target_skus` 成熟模式），把"结果待核实"收敛为"已入库/提交失败/需人工"。
2. **结构化错误码替代中文关键词匹配**：`"登录" in text or "验证码" in text` 决定 paused/error（`desktop/jobs.py:1197、1187`），上游文案一改即错分状态 → 上游抛带 `reason` 的异常类型（login/captcha/slider/timeout），下游按码分流。
3. **步骤级超时与看门狗**：取消纯协作（`jobs.py:936-943`），某步卡死任务永远 running → 每阶段加预算超时 + watchdog；结果 xlsx/json 增量落盘而非仅整批结束写（`jobs.py:1121-1175`）。

### P1 — 可靠性
4. **checkpoint 双写**：断点只存在页面 sessionStorage，浏览器崩溃即丢 → 将 payload 哈希 + completed 步骤集合同步写进 job_session.json，恢复时与页面 probe 合并判断。
5. **异常静默吞噬治理**：`except Exception: pass` 遍布关键路径（`jobs.py:366-368` 会话保存、`jobs.py:1090-1091`、`pipeline.py:590,614,620`、`app.py:84-87`）→ 至少记日志并上报 UI，持久化失败必须可见。
6. **日志体系统一**：desktop.log 无轮转（`jobs.py:326-331`）；诊断分散在 web_fill_*.json/raw.txt/progress.json/desktop.log/job_session 多处 → RotatingFileHandler + 结构化事件（stage/attempt/result）单文件输出，前端日志面板加级别/关键词过滤。
7. **素材核验差异结构化存储**：核验结论（如"13/15 一致，2 处 CDN 差异"）目前只进文本 → 设计"部分通过"状态位 + 差异明细 JSON，便于人工续审（对应 AGENTS.md 的分项差异记录要求）。
8. **必填属性下沉模板 JSON**：`CATEGORY_ATTRIBUTES` 硬编码在 `千牛自动上架.py:24` → 移入 templates/attributes/*.json，加类目不改代码。

### P2 — 长期
9. 双执行器收敛（`千牛网页执行.py` 1657 行旧路线降级为基础库、删死代码）；选择器定位集中到统一 probe 层（probe_state.js 扩展），减少各脚本各自爬 DOM；版本号三处硬编码（pack.ps1:235/installer.iss:2/update.iss:2）统一管理 + 应用内更新检查；会话合并以 product_id 为主键替代 row 号（`job_session.py:342-346`）；为 `商品解析.scan_image_pack` 补独立单测；主视频/详情图建立真实页面验收清单脚本。
