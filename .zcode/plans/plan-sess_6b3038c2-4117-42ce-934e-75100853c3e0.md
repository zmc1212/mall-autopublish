# 入库时间统计功能设计与实施计划

## 功能口径

- **"一次入库" = 一次点击「开始入库/继续入库」到任务结束**(完成/暂停/停止/失败)。现有 job 模型中暂停后继续会新开一段任务,因此每段单独计一条记录,暂停等待人工处理(滑块/登录等)的时间天然不计入时长,无需额外扣减逻辑。
- **每条商品耗时** = 该商品从「开始填写」到处理结束的墙钟时间(含建品+提交+补图核验),跳过的商品不记录(显示 "—")。

**2. 执行明细弹窗——每条商品耗时**:表格在「图片状态」后加「耗时」列,显示每条本次入库耗时(如 `3分25秒`),未执行的显示 `—`。

**3. 入库成功通知卡(RunNotifications.tsx)**:文案下追加一行 `本次耗时 3分25秒`(有记录时)。

**4. 「耗时统计」历史弹窗(新增,复用 DataTableDialog)**:列出最近 30 次入库任务,列为:开始时间 / 总时长 / 平均每条 / 处理条数 / 成功 / 失败。描述注明"每次开始/继续入库记为一条,暂停等待不计入;旧版本任务无记录时显示 —"。

## 后端改动

### desktop/jobs.py
1. **任务级计时**:`__init__` 加 `self.started_at = 0.0`、`self.finished_at = 0.0`、`self.item_durations = []`。`start_job`(jobs.py:941)设 `started_at = time.time()` 并清零另两者;`_run_job` 正常结束分支(jobs.py:1278-1291)与异常分支(jobs.py:1296-1307)设 `finished_at`。`import_workbook` 非 restoring 时重置。
2. **snapshot()**(jobs.py:285)新增字段:`started_at`、`finished_at`、`elapsed_seconds`(运行中 = now-start,结束 = finished-start,空闲 = None)、`avg_item_seconds`(本段任务真实处理条目的耗时均值)。前端 1.2s 轮询自动刷新计时器,时钟以后端为准。
3. **每条计时**:`_run_job` 内加 `item_started = {}`;`on_start`(jobs.py:1109)记录起始时刻;`on_done`(jobs.py:1119)计算 `duration_seconds = round(now - start, 1)` 写入 `item`、`rows` 对应行、`products[].meta`(后者使 journal JSON 自动带上)。跳过分支(未走 on_start)不写该字段。
4. **serialize_row**(jobs.py:174)输出加 `duration_seconds`;`_pending_products` 的回填字段列表、`clear_row_state` 的 `clear_keys` 同步加该字段。
5. **持久化**:`_session_payload`(jobs.py:387)与 `_ensure_restored`(jobs.py:425)带上/回填 started_at、finished_at,重启后仍显示上次时长;`_run_job` 结尾 journal JSON payload(jobs.py:1269)顶层加 `started_at/finished_at/duration_seconds/total/done`。
6. **xlsx 处理日志**:entries 构造(jobs.py:1255)追加第 9 列「耗时」格式化字符串;新增 `format_duration(seconds)` 工具函数(xlsx 与后端共用)。

### 千牛自动上架.py
- `write_log` 表头(543 行)与建模板处的处理日志表头(719 行)末尾加「耗时」列。`stamp_list_item_ids` 按索引 7 取淘宝商品ID,追加尾列不影响。

### desktop/server.py
- 新增 `GET /api/job/history`(放在 StaticFiles 挂载前):扫描 `settings.results_dir` 下 `*.结果-*.json`,按修改时间倒序取最近 30 个,解析出 `started_at/finished_at/duration_seconds/total/succeeded(有淘宝商品ID的条数)/failed(execution=失败条数)/avg_seconds`;旧文件缺字段返回 null。

## 前端改动(desktop/ui)

1. **types.ts**:`WorkbookRow` 加 `duration_seconds?: number`;`JobState` 加 `started_at/finished_at/elapsed_seconds/avg_item_seconds`;新增 `JobHistoryEntry` 接口。
2. **api.ts**:加 `jobHistory()` 调 `GET /api/job/history`。
3. **utils/formatDuration.ts(新)**:`formatDuration(seconds)` → `45秒` / `3分25秒` / `1小时23分`,空值返回 `—`。
4. **RunPanel.tsx**:统计条改 4 列加「平均每条」;进度条下方文字运行中追加 `已用时`、结束后显示 `总耗时`;按钮行加 ghost 按钮「耗时统计」(Clock 图标)打开历史弹窗(内部管理 open/loading/分页状态);执行明细表格加「耗时」列(colgroup、表头、单元格同步加,min-width 相应加宽)。
5. **RunNotifications.tsx**:成功卡片加耗时一行。
6. App.tsx 轮询机制无需改动,新字段随 `/api/status` 自动到达。

## 测试与验收

- test_desktop.py 新增(unittest):serialize_row 带 duration_seconds;snapshot 任务计时字段;job_history 解析结果 JSON(含旧格式兼容)。

## 兼容性

- 旧 journal/旧 rows 无耗时字段 → 界面显示 "—",不影响续跑逻辑(duration_seconds 不参与任何流程判断)。
- xlsx 处理日志新增尾列,旧表头文件由 write_log 重写表头,自动对齐。
