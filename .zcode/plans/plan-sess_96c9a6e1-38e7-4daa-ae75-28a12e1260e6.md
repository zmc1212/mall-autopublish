## 目标

自动入库从「一条卡住 → 整批暂停等人工」改为「一条卡住 → 自动重试 N 次（设置可配）→ 仍失败自动跳下一条」，一次点击跑完全程；跑完后统一汇总所有需人工处理的条目。唯一保留的中断手段是用户主动点「暂停任务」。

已确认的策略：
- 登录失效/滑块/验证码（重试也无用的硬暂停）：不重试，标记该条后**跳过继续**，跑完统一处理。
- 「提交待核实」（可能已建品，按现有规则禁止自动重复提交）：**不重试**，标记后跳过继续。
- 其余明确失败（超时、元素未找到、规格未写入等）：自动重试 N 次，重试 = 复用现有断点续跑机制（flow_stage + 页面 sessionStorage checkpoint，跳过已完成步骤），不是盲目从头重做。

## 改动内容

### 1. 新设置项 `item_retry_limit`（条目自动重试次数）
- `desktop/paths.py`：`Settings` 加 `item_retry_limit: int = 1`（0 = 失败不重试直接跳下一条）；`normalized()` 钳制 0–5；`load_settings()` 读取。
- `desktop/server.py`：`SettingsIn` 加字段（ge=0, le=5），`put_settings()` 合并保存。
- `desktop/ui/src/types.ts` `AppSettings`、`App.tsx` `EMPTY_SETTINGS`（默认 1）、`SettingsPanel.tsx` 新增数字输入项，说明文案含「重试用尽后自动跳过该条继续下一条；登录/滑块等需人工的情况不重试直接跳过」。

### 2. `web_fill/pipeline.py` — run_batch 条目级重试（核心）
- `run_batch()` 签名加 `item_retry_limit: int = 0`（CLI 旧入口默认 0，行为不变）。
- 在 `pause_reason_code` 附近（~1171-1235）新增判定 `item_retryable_notice()`：命中 登录/验证码/滑块、SessionLost、提交待核实/STAGE_SUBMIT_PENDING、残留文件选择器、结果不明确/结果待核实/禁止自动重复/操作过于频繁（上传安全限制）的**不可重试**；其余失败可重试（符合 AGENTS.md「结果不明确不得自动重复执行」）。
- 把单条处理体包进 `while True` 重试环，原来 5 处整批 `break`（pipeline.py:2740 硬暂停、2747 提交待核实、2759 失败/暂停、2799 SessionLost、2820-2822 兜底）改为：重试或标记后 `need_new_tab=True` 进入下一条。
  - 可重试失败且次数未用尽：把本次尝试产生的 `flow_stage/taobao_item_id/sku_material_manifest` 等状态合并回 product（从断点续跑），best-effort 清理遮罩与导入弹窗（`_maybe_close_overlays`/`_dismiss_import_dialog`），重试。
  - 次数用尽或不可重试：落盘失败状态后跳下一条。
  - 仍保留整批中断的仅两种：用户 cancel（cancel_event/UserStopped）、店铺账号不一致（2563-2572）。
  - `on_item_done` 只在条目最终定论时调用一次，`updated` 每条只存最终结果，避免 done 计数被重试虚增。

### 3. `desktop/jobs.py`
- `run_batch` 调用传入 `item_retry_limit=settings.item_retry_limit`。
- 新增 `on_item_retry` 回调：写日志「第 N 行第 k/上限 次自动重试」，phase 显示「第 k 次重试」。
- 收尾状态聚合（现 1492-1562 行依赖「批内是否中断」判断 paused）：改为统计 execution ∈ {失败, 暂停, 提交失败, 提交待核实} 的行——存在则 `status="paused"`、`phase="需人工处理"`，blocker 为「N 条需人工处理」+ 各条原因摘要；全部成功才是 done。
- `_finish_browser` 的保留现场集合加入「提交待核实」；中途命中登录类暂停时保持现有弹浏览器行为（方便趁跑批时人工处理）。

### 4. 测试
- `test_web_fill.py`（沿用现有 fake session 模式）新增用例：失败 1 次重试后成功、重试用尽跳下一条继续、硬暂停跳过继续、提交待核实不重试、用户取消仍整批停止、重试时从断点续跑（flow_stage 合并正确）。
- `test_desktop.py`：`item_retry_limit` 设置往返与 0–5 边界校验。
- 跑全部现有测试确认无回归。

### 5. 规则与验收说明（AGENTS.md）
- 滑块/验证时仍「保存阶段」（checkpoint 机制不变），仅把整批暂停改为标记+跳过+跑完汇总——这是你本次明确要求的策略调整。
- 上传/采纳结果不明确类维持「不得自动重复执行」，只跳过不重试。
- 模拟测试通过后，需一次真实页面冒烟验收（由你操作）才能给出最终结论；未完成前结论按规则记为「无法判断」。
